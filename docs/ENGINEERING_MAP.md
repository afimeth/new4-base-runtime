# Connected engineering domains

The [AI Engineering from Scratch](https://aiengineeringfromscratch.com/) homepage describes four connected domains. This original mapping links those domains to this repository's actual work; it does not claim course completion or reuse course artifacts.

| Domain | Implemented here | Evidence / open boundary |
|---|---|---|
| Building AI applications | Context ingestion, source lookup, CPU ranking, typed proposals, persistent workflow | Local behavioral tests; no model training, live LLM or semantic calibration |
| Software engineering foundations | Python/Go process protocol, SQLite recovery, bounded gateway, UTF-8, WSL execution | Actual subprocess/restart/concurrency tests; no production-scale operation |
| Agent-assisted engineering | Scoped case capsules, worker/provider registry, context prefix and source map, retained feedback | Implemented harness and deterministic worker; no universal model dispatch |
| Product judgment and delivery | Common-language request, clear approval, simple UI, testable hypotheses and limitations | Live local walkthrough; independent user utility remains UNKNOWN |

The point is a connected work environment: each capability has a role, an interface, a state/effect boundary and inspectable evidence. A reference topic does not become an implemented capability merely by appearing in this table.
